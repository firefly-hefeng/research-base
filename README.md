# Research Base 科研文献与前沿研究基础组件

Research Base 是可嵌入科研工作流和 agent 体系的基础组件，帮助研究者**建立、维护和使用研究方向的前沿文献基础**，并将相关前沿论文及原文细节注入选题分析、研究设计和结果解释。

它连接多源文献发现、全文与材料获取、本地资料管理和科研 agent 的实际阅读与核验。论文、作者代码和材料原件是主要知识来源；前沿参考空间、目录和索引帮助研究者找到并使用这些知识。当前提供可运行的 Python 内核、CLI、可选 MCP 和 DeepSeek 工具调用 agent，多项目可共享本地原件和索引。

## 重要功能

| 功能 | 为研究提供的帮助 |
| --- | --- |
| 多源文献发现 | 提供 10 个来源适配器，按方向组合综合索引、预印本、生物医学索引及学科来源；支持分页、时间范围、来源专用查询和请求预算。ACL Anthology 与 bioRxiv 按需显式启用。 |
| 种子恢复与引用扩展 | 按论文身份找回重点文献，扩展参考文献及后续引用，补充单次关键词检索容易遗漏的工作，并保留来源与续接状态。 |
| 全文与材料获取 | 开放接口优先获取 PDF、PMC 原始 JATS 全文及材料链接；缺失项可由宿主后台浏览器接续，利用已有会话，不占用系统鼠标键盘。文件经过论文身份、版本和完整性检查后纳入。 |
| 本地文献与原件管理 | 管理论文标识、版本、集合、纳入状态、标签及附件，支持 BibTeX、RIS、CSL JSON、Zotero API JSON 导入；提供原始文件路径、检索、文本续读和 bundle 导出。 |
| 建立前沿研究基础 | 按研究方向维护文献集合，精选关键近期工作和必要基础文献，形成可更新的前沿参考空间，为研究问题、基线、评价指标、方法条件及局限的分析提供原文依据。 |
| 按任务注入前沿研究 | 根据当前任务、研究阶段及学科准备相关论文入口、阅读问题、材料缺口和检索更新建议，让 agent 在具体决策前实际查阅相关论文及必要代码。 |
| 阅读与关键细节核验 | 记录实际返回的原文范围及续读状态，将关键解释绑定到原文片段，并独立复核关键细节和实际最终稿；缺少必要材料或核验时保留待完成状态。 |
| 接入研究工作流 | 通过 Python、CLI、MCP 和 DeepSeek agent 连接现有体系；使用受管的局部 AGENTS.md v4 写入研究规则，支持安装、更新与卸载。 |

来源及覆盖限制见[文献来源](docs/sources.md)，后台获取方式见[后台浏览器获取](docs/background-browser.md)。XML 按逻辑章节导航，PDF 按物理页导航。

## 如何建立前沿基础并注入研究

1. **为研究方向建立文献集合。** 明确研究问题、来源及时间范围，结合主题广检索、重点论文恢复和引用扩展收集候选，筛选纳入相关工作，精选持续可见的关键前沿入口。
2. **准备可直接利用的原始资料。** 获取论文全文，保留代码、数据及补充材料入口，记录版本和缺口。科研 agent 可以自行检索、浏览、选择并读取所需原件；同机可直接使用文件路径，远程模型通过读取工具获得内容。
3. **将前沿接到具体研究任务。** 绑定研究项目并写入局部 AGENTS.md；任务开始时通过 `prepare_research` / `begin_research` 查看相关前沿、更新范围、阅读问题和材料入口，再围绕当前决策实际阅读原文及必要材料。
4. **在方案与结论提交前核对细节。** 检查方法条件、指标定义、实验划分、基线角色及适用边界，完成原文续读和必要的独立复核；已有证据、提出的新设计与待验证假设分别说明，使后续研究以已知前沿为起点继续探索。

绑定项目或集合的内置 agent **默认执行严格研究流程**：任务相关的必读选择、实际原文阅读、当前检索范围的新鲜度检查、关键细节及最终稿核验。未满足要求时不交付为已完成的严格研究。显式探索模式可用于早期思考，结果会标明尚未完成严格核验。

局部 AGENTS.md 负责声明研究规则；外部 agent 宿主还需要实际加载规则，并将检查接到方案或结论的提交步骤。仅连接 MCP 或写入规则文件，不会自动拦截任意宿主的输出。接入细节见[研究知识接口](docs/research-knowledge-interface.md)、[关键细节核验](docs/checked-reading.md)及[规则管理](docs/agent-integration.md)。

例如，RAG 研究可围绕当前工作核对时间冲突、答案与证据评价和高相似冗余；单细胞扰动研究可核对泛化划分、适配的信息预算、DE 指标及风险边界。研究者仍可提出不同的新方法，并明确哪些约束来自原文、哪些选择需要通过实验验证。

## 开始使用

需要 Python 3.11 或更高版本。安装后执行 CLI；Windows 的完整步骤见[快速开始](docs/quickstart.md)。

```text
python -m pip install -e ".[mcp,dev]"
research-base --help
research-base sources list
```

本机验证生成了示例集合与材料入口 `.research-base/demo.json` 和 MCP 配置 `.research-base/mcp-config.json`。这些文件位于忽略目录，不随仓库提供；新克隆项目应按快速开始创建自己的库、集合和路径配置。

## 验证状态和边界

最近一轮完成 533 项离线测试、真实 MCP 连接，以及 RAG 评价与单细胞扰动两个用例的 12 个前沿注入对照样本，并经过[多 agent 交叉议会](docs/council-core-upgrade.md)评审。已知的四项重点论文或版本漏检通过修订查询找回；单细胞原集合可读正文从 54/109 增至 79/109，RAG 为 20/24。严格研究组交付 3/4，其余样本保留核验缺口。详见[核心能力升级](docs/core-capability-upgrade.md)与[前沿注入对照](examples/frontier-ablation/README.md)。

本次已知用例中，实际原文有助于完善部分研究方案细节，仍存在模型误读和未交付情况；尚未证明普遍科研收益、净节时或实验性能提升。前沿参考空间只覆盖明示来源、时间和已完成检索范围，检索暂停、缺失全文及版本歧义均保留。后台浏览器由具备相应能力的宿主接续，尚无适用于全部站点的通用无人值守获取保证。原文和模型复核均需结合研究者判断及真实实验。

此前的[前沿更新](docs/frontier-refresh-validation.md)、[原文与细节核验](docs/checked-reading-validation.md)和[研究工作流验证](docs/research-validation-round3.md)保留历史运行及改进过程。原始论文、作者代码原件、密钥和本机运行包保留在执行机器。

## 首版使用闭环

输入研究方向 → 开放接口检索 → 合并候选并确定纳入范围 → 尽量获取全文 → 未获取项交给宿主浏览器 → 建立本地可检索材料集合 → 将集合接入研究项目 → agent 在研究关键节点检索并读取相关原件。

首版按单机部署，同机可有多个研究项目共享一个本地库。实验室多成员服务化、远程文件上传与多用户权限管理在后续阶段实现。
