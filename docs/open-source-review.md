# 开源文献工具的可借鉴设计

Research Base 应优先帮助研究者迁入已有文献、组织原始材料，并让科研 agent 按任务选择和读取资料。参考 Zotero、PaperQA2 和 ASReview，当前最值得投入的是标准格式导入、轻量集合与标签导航、任务级检索，以及可解释的新鲜度和覆盖状态。文献数量、下载成功数量和模型返回篇数都不能单独证明已经掌握研究前沿。

日期：2026 年 11 月 2 日。下文的采用项是开发取舍，实际可用状态以实现、测试和真实用例记录为准。

## 参考工具和适用边界

| 工具 | 官方能力依据 | 对 Research Base 的意义 |
| --- | --- | --- |
| Zotero | 支持多种文献交换格式，集合与标签用于组织条目；同一条目可属于多个集合而不复制条目。[导入格式](https://www.zotero.org/support/kb/importing_standardized_formats)、[集合和标签](https://www.zotero.org/support/collections_and_tags) | 接入研究者已整理的书目，保留其组织方式，减少重新检索与反复下载 |
| PaperQA2 | 在文件索引之上提供搜索、按问题选择内容和生成答案的工具；agent 可以组合宽窄不同的搜索，并复用已有索引。[项目 README](https://github.com/Future-House/paper-qa/blob/main/README.md) | 借鉴任务驱动的搜索和读取，不要求在入库时为所有未来问题预写结论 |
| ASReview | 用已知相关或不相关的记录作为先验，帮助安排候选筛选顺序；筛选结果可保存和调整。[建立评审](https://asreview.readthedocs.io/en/stable/lab/project_create.html)、[筛选流程](https://asreview.readthedocs.io/en/stable/lab/screening.html) | 把候选筛选与全文获取分开，优先减少研究者在大量不相关候选上的时间消耗 |

这些工具解决的问题不同。Zotero 的组织模式可直接借鉴；PaperQA2 的回答流水线适合接在材料库之上；ASReview 的主动学习适合候选量大且有标注的筛选任务。Research Base 无需把它们各自的完整运行环境合并到内核。

## 优先改进

### 现有书目导入

**现在采用：** 提供 BibTeX、RIS、CSL JSON 和明确命名的 Zotero API JSON 导入入口。研究者可以把已有文献管理器或数据库导出的条目转为 collection 候选，再决定纳入并补齐全文。Zotero 官方列出 BibTeX、RIS 和 CSL JSON 等交换格式，同时说明 RIS 存在不同实现的字段差异。[格式说明](https://www.zotero.org/support/dev/data_formats)

导入至少保留标题、作者、年份、DOI、摘要、关键词或标签、原始来源 ID 和可用 URL。每条记录给出导入成功、重复、跳过或解析失败的结果；重复执行不应增加相同来源记录。无 DOI 的条目使用来源标识和导入记录身份保存，不靠标题相同自动合并。

CSL JSON 与 Zotero API JSON 分开处理。前者通常使用 author 等引文数据结构；后者使用 Zotero 条目类型、creators、tags 等字段，并可能包含 data 外层及独立附件条目。Zotero API 的 JSON、条目字段及创造者类型由其 API 文档定义，不应把任意 JSON 列表当作相同格式。[API JSON 与读取方式](https://www.zotero.org/support/dev/web_api/v3/basics)、[类型与字段](https://www.zotero.org/support/dev/web_api/v3/types_and_fields)

书目文件中出现本地附件路径时，默认保留为待关联信息；只有研究者显式启用本地附件导入后才读取文件，并经正常材料校验。远程 URL 默认登记入口，下载由获取任务完成。缺失附件要报告，不能把书目导入成功当作全文已经取得。

**后置：** Zotero 在线双向同步、自动写回用户库和复杂目录镜像。离线交换已能减少迁移成本，双向同步还涉及删除、版本冲突和账户权限，应在明确需求后单独实现。

**验收重点：** 多作者、BibTeX 嵌套花括号、RIS 重复作者字段与多行摘要、中文元数据、两种 JSON 形态、重复导入及缺失附件。不要用只能解析单行字段的示例证明已支持真实书目格式。

### 集合和标签导航

**现在采用：** 同一 paper 可进入多个 collection，原件只保留一份；加入或移出集合只改变成员关系。增加轻量标签，并让 list_papers 支持无检索词浏览、成员状态及标签过滤。Zotero 将集合用于项目或主题分组，将标签用于方法、状态或其他细粒度特征。[集合和标签模型](https://www.zotero.org/support/collections_and_tags)

建议将科研项目自己的方法或用途标签放在 collection membership 上，避免一个项目的“待复现”状态自动影响另一项目；书目自带关键词可保留为来源元数据。标签不替代 candidate、included、excluded 这些明确的集合状态。

默认返回标题、年份、来源、纳入状态和材料可用性。科研 agent 可以先浏览集合，再调用 list_materials 获得 PDF、代码及补充材料入口；无需为浏览资料先拼接一个检索式。标签更新应有显式的添加和移除操作，不能在导入时覆盖研究者已有标签。

**后置：** 多级目录、标签本体和自动主题聚类。首版先保证成员关系、分页和过滤正确；复杂组织方式应根据实际集合规模决定。

### 按任务扩大召回并读取原件

**现在采用：** 允许科研 agent 以任务、同义词及来源专属检索式多轮发现；本地先做较宽的候选检索，再由 agent 自主选论文、页码和材料。当前任务的片段只是导航，始终提供可读取的原件路径及材料 ID。PaperQA2 的搜索和内容选择工具可由 agent 组合调用，索引可复用，这支持“资料长期保存，内容按任务选择”的方向。[搜索和读取工作流](https://github.com/Future-House/paper-qa/blob/main/README.md#paperqa2-algorithm)

同机宿主可以直接打开材料路径；模型 API 服务本身不能凭一个本地路径读取文件，应调用 read_material 或由宿主传入内容。原文阅读要支持页码、字符预算和续读定位，避免 agent 每次只能拿到同一段开头。

**后置：** 向量检索、模型重排和对每段内容生成摘要。先用真实任务检查关键词与中文回退的漏检，再决定哪个附加检索器能改善结果。不在入库阶段强制调用模型为每篇论文制作知识卡。

**验收重点：** 研究者准备一组已知相关论文，用相同任务检查它们是否可被找回、相关材料是否可打开，以及 agent 是否读取了必要原文。比较增加同义词或第二来源前后的结果，而不是只比较返回数量。

### 前沿新鲜度和检索范围

**现在采用：** 将来源、来源查询、时间范围和其他影响召回的条件保存为检索计划；完整执行时间、实际覆盖截止时间、暂停原因及逐来源状态分开记录。检索预算耗尽、某个来源失败、仅下载完已有论文，都不能刷新整个方向的“检索已完成”状态。这是针对 Research Base 工作流提出的工程设计，不是对上述工具能力的推断。

任务上下文同时显示计划是否改变、何时完成过相同范围的检索、覆盖到什么日期，以及相关论文有哪些仍缺全文。固定检索历史年份的计划即使刚执行完，也不能被描述为已检查当前最新研究；当任务要判断前沿时，应显式检索相应的新近时间范围。

**后置：** 全自动定时监测、复杂的研究趋势仪表盘和“前沿得分”。先让单次检索的范围与状态可靠，再增加自动调度。

### 候选筛选和种子论文校验

**现在采用：** 保留可修改的 candidate、included、excluded 状态，可登记少量研究者认可的相关种子论文。种子用于检查检索计划是否漏掉已知基础工作，并帮助调整关键词和来源。ASReview 的已知相关或不相关记录用于产生初始及后续排序，其筛选流程保留研究者决策。[先验与筛选](https://asreview.readthedocs.io/en/stable/lab/project_create.html#prior-knowledge)

采纳的是“利用已有知识减少无效筛选”，不要求首版训练主动学习模型。agent 可提供候选排序或纳入建议，但不能因相关性排序较低而删除元数据，也不能把论文暂时获取失败当作排除理由。

**后置：** 主动学习训练与自动停止筛选。ASReview 的进度功能提供停止策略的辅助信息；是否停止仍涉及工作范围和策略选择，不能把连续若干篇不相关直接解释为已找到全部相关研究。[筛选进度与停止](https://asreview.readthedocs.io/en/stable/lab/progress.html)

## 本轮实现顺序

优先交付标准书目导入和集合浏览，再补轻量标签过滤；同时确保任务级原件读取与新鲜度状态准确。种子论文可以先通过已有的手动元数据导入和集合纳入功能表达，后续再增加专门界面。

真实用例应同时展示：从已有书目迁入、从多个来源发现新项、按任务筛选相关论文、直接读取原件或代码入口，以及更新和失败状态。记录导入条数、去重结果、种子召回、全文可用性和实际阅读的材料即可；不创建逐篇证据文档，也不以下载量作为前沿覆盖的保证。
