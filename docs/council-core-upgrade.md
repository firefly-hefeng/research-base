# 本轮多 Agent 交叉评审

评审围绕两项核心能力，由三个席位交叉检查发现、获取、研究门禁与真实对照，主 agent 汇总并修复。模块作者不单独决定本模块验收。原文与私有运行包留在本机；公开记录只保留问题、结果和边界。

| 优先级 | 发现 | 处理与验证重点 |
| --- | --- | --- |
| P1 | bioRxiv 新来源的版本日期字段与 PDF 导入核对字段未贯通，存在同 DOI 不同修订错配风险 | 官方来源候选到文件导入的整链回归；错误 posted-date 必须暂存，不能仅凭 DOI 接收 |
| P1 | 公开解析路径只检查初始 URL，重定向可能进入非公开地址 | 每一跳请求前检查目标；浏览器内已授权访问仍走独立路径 |
| P2 | 同页换页码组合复读产生假续读缺口 | 仅合并同一实际原件、版本及哈希的逐页覆盖；中间漏读、改版仍阻断 |
| P2 | 受限材料的相邻页读取会越过宿主允许范围 | 仅返回许可邻页，报告 omitted_neighbors，不暗读或扩权 |
| P2 | 未绑定查询可能被误认为严格研究完成 | `unbound_completed` 与严格完成分开，保留普通管理查询 |
| P2 | PDF help 的非 HTTP 链接可遮蔽后续合法正文链接 | 跳过不可用链接，仍校验最终下载、字节、论文及版本 |
| P2 | 复核把明确待验的新研究设计当作文献必须已证明的事实；拒绝理由又未反馈给研究 agent | 区分文献断言与原创假设，反馈有界拒绝原因；不因“未运行”自动拒绝方案，也不放过来源冲突 |
| P2 | 评测脚本把已通过最终稿审核的预算受限结果计作无交付 | 按可信终稿验收回执计量，限额原因另列 |

评审另指出同模型评分的实质局限：它可能给稿件不存在的定义加分，把诚实的“未读”声明当作错误，或把未交付与材料事实错误混为一谈。因此保留原始盲评，并对最终两例进行基于实际原文的独立复核，不用模型总分替代逐项结论。

这两个任务参与了开发调试。固定协议下不择优替换样本，并不意味着它们是未见任务；最终对照属于已知用例回归。严格流程增加了规则、规划与复核和计算成本，不能把差异全部归因于论文注入，也不能推断净节时或实验性能提升。

获取审查实际拦住了一份来源 URL 与目标一致、PDF 首页 DOI 和标题却属于另一篇论文的错件。它保持暂存，未计入可读全文；当前证据不足以判定站点、缓存或传输中的具体原因。PDF 原件可读、文本抽取完整以及精确版本满足仍是三项不同判断。

版本日期修复后，对本轮浏览器返回和同字节重验的 27 条材料记录进行了只读复查。16 条可读且已归属版本的记录均属于旧来源的通用预印本 edition，没有依赖新来源的日期字段；因此不需降低当前正文可读分母，也不能将它们升级宣称为精确修订已核验。

最终版本离线测试 533 项通过；另以真实 MCP stdio 连接验证了接口调用。公开文件检查还会在发布前对最终文件集合重新执行，原文、密钥和本机运行包不在导出集合内。
