# 两项核心能力升级（2026-11-03）

本轮围绕广泛发现并收集文献，以及让研究实际使用前沿原件展开。原文、代码与材料仍是知识主体，不增加逐篇证据卡。检索计数、可读全文、版本满足及研究输出质量分别验收。

## 发现重点文献

新增官方 bioRxiv 元数据来源，补充单细胞的 arXiv 查询，并扩大 RAG 的标题及摘要查询词。bioRxiv API 不提供通用全文关键词搜索：适配器按明确日期和学科分类分页，再本地筛选标题及摘要；这一路线可能需要较多请求，不能将预算暂停当成完成。

此前漏检的 PIE、State 正式版、VCBench 和 EBG arXiv 版本，都已由修订后的普通主题查询实际返回。这是看到漏检后设计的回归，不是盲测，也不能据此估算全领域召回率。同标题但无明确版本关联的 ACL / arXiv 记录继续分开。

来源、查询范围、实际请求与分页状态见[发现回归摘要](../examples/core-upgrade/discovery-regression.json)。新建议不自动执行网络请求、改变纳入集合或改写新鲜度；旧查询的有效更新记录不为新查询背书。

## 可靠获取和原件导航

PMC 官方元数据明确给出 XML 原件时，支持下载并解析 JATS 全文，严格核对正文文章元数据中的 DOI、标题和仓储修订；参考文献中的 DOI 不作身份依据。XML 使用逻辑章节，保留原件路径，并明确不是 PDF 物理页码。

后台浏览器使用任务标签页和实际观察到的正文入口，识别 citation_pdf_url，排除 `.pdf+html` 预览，不控制系统输入。字节及整体哈希正确后仍需核对论文和版本。正文明确是预印本时，不将旧 accepted / unknown 元数据当作该原件的匹配版本；若有多个修订而无法唯一匹配，继续保留版本缺口。

纳入分母、全文与 PDF 增量、版本目标及剩余障碍见[获取摘要](../examples/core-upgrade/acquisition.json)。下载或可读不代表无抽取遗漏；复杂公式、图表及解析警告需要查看原件。

## 默认研究流程

绑定项目或集合的内置 agent 默认执行 strict：按任务规划少量关键问题、实际读取相关原件、提交解释与原文地址、由独立调用复核关键细节、核对配置范围的新鲜度，再审核实际最终稿。只接受与审核稿件完全一致的文本；有材料、上下文或核验缺口时保留阻塞，不发出已完成严格研究的结果。

局部 AGENTS.md v4 要求使用这些接口；安装规则与真正执行拦截是两回事。外部宿主需要把检查接到提交步骤，不能仅凭写入规则推定任何 agent 已受程序约束。可以显式选择 explore，但结果不属于严格研究完成。

同机科研 agent 可直接使用原始资料路径；远程模型须通过工具读取。默认模型复核只接收本会话实际返回且允许使用的上下文。原文传给外部服务仍由宿主确定授权范围，公开仓库不包含论文原文、作者代码原件或本机库。

## 实际对照

两真实用例采用同一任务、模型和公共提示，各两次独立生成，比较无原文注入、仅注入实际原文、默认严格流程三种条件。额外调用量不同，分别报告成本与交付率；评分不以论文名称或工具次数加分。协议、失败样本与最终结果见[对照说明](../examples/frontier-ablation/README.md)。同模型独立评分有相关偏差，研究方案评分不等同实验效果或效率提升。

三个席位的交叉评审与修复见[议会记录](council-core-upgrade.md)。

最终严格组交付 3/4，另一份单细胞方案因 DE 关键点尚未核验而保持阻塞。独立原文复核支持这两个已知用例的部分方案细节改善，同时仍发现误读和设计归因问题；尚不能据此证明普遍科研收益或净节时。
