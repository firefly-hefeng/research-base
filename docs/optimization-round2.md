# 第二轮召回引用和获取优化

本轮围绕上一轮议会提出的种子漏检、引用扩展和全文获取稳定性改进。目标是让研究者从当前任务进入相关的基础工作与近期研究，再自主读取论文、代码和材料原件。实现继续使用轻量目录和可重建索引，不增加逐篇知识卡。

本文记录已落地的接口、验证结果与实现边界。两个既有用例使用原研究问题和种子集合复跑，保留首轮报告，分别记录召回、引用候选和全文状态。

## 真实来源的种子恢复

原有 discover_papers 保留为普通多源检索。新增 discover_frontier 把主题广检索与已知种子恢复组织成同一可续接任务：先保留广检索的真实来源命中，再对未命中的种子查标识符或核对来源返回的题名信息。

seeds 是待查身份，至少含 title、doi、arxiv 或 pmid，可补 authors、year、seed_id。种子输入不直接生成候选，本地缓存中已存在的同一论文也不计为本轮来源召回。提供方错误与确定未命中分开表示，避免把限流或服务故障当作文献不存在。

| 进度字段 | 使用含义 |
| --- | --- |
| broad_job_id | 对应普通主题检索任务，可继续检查各来源状态 |
| broad_recall | 仅用该广检索命中快照计算已知种子 found/total |
| seed_coverage | 在广检索与来源查回后计算已知种子 found/total |
| seeds | 每项的 status、paper_ids、broad_paper_ids、attempts 等状态 |

广检索身份快照独立保存。后续查回更新了同一论文的元数据，也不能反过来将旧快照变成广检索已命中。预算很小时跨续接保留进度，让待查种子有机会执行，而不是一直被广检索分页占满。

budget.max_requests 是本轮预算，broad_requests 可固定其中的广检索份额。对照用例可保留相同的广检索 4 次请求，再单独记录用于种子查回的追加请求。请求按提供方工作单元推进，须同时报告实际次数与可能的预算超出；增加查回请求后不能只比较命中数而忽略成本。

CLI 为 frontier --collection --query --seeds，模型工具直接接收结构化 seeds 数组；模型没有由此获得读取任意种子文件的能力。命令、参数和示例见[快速开始](quickstart.md)及[Agent 接口](agent-api.md)。

## 独立的一跳引用图

新增 expand_citations，按已存在的 paper_id 查询后续引用或参考文献。每个起点和方向是独立的可续接流，保留提供方、游标、完成状态和错误；新文献以 candidate 加入集合，原有 excluded 状态保留。

citation_edges 按实际方向保存 citing_paper_id、cited_paper_id 与 provider。重复页面和重复执行不会重复增加同一条关系，起点自身及已确认的同一工作版本不作为新的自引用扩展收益。

progress.streams 展示每条流的 cursor、provider、complete 等状态，paper_ids 给出实际候选，edges_added 给出新增关系数量。direction=both 同时执行前向和后向流；它是对每个起点做一跳，不是递归遍历整个学科图谱。

引用扩展的完成不写入主题检索的 search_runs，也不刷新另一个主题范围的新鲜度。研究者应对新增候选继续做任务相关性判断，引用量和引用连接本身不等于高质量或支持某结论。

## 全文获取分阶段回退

获取调度先尝试已有的 PDF 位置；没有满足目标时继续 metadata 阶段，再进入 fallback 阶段。这样已经有可用主文时无需执行所有较重的解析请求，失效链接也不会提前阻断后续公开路径。

| 阶段 | 当前职责 |
| --- | --- |
| known_location | 尝试文献已有的全文位置，保留文件与目标校验结果 |
| metadata | 已知 arXiv 标识、OpenAlex OA 元数据，以及明确配置时的 Unpaywall 位置 |
| fallback | PMC 公开元数据、提供方明确的预印本关系及身份匹配的论文页 PDF 元数据 |
| 宿主浏览器 | 公开路径未满足后，通过租约、下载目录和文件交回继续获取 |

标准论文页解析使用 citation_pdf_url 或 PDF alternate 等明确元数据，并核对论文标识；不为出版社拼猜下载路径。网络响应有界，HTML 登录页不作为 PDF。PMC 版本和候选位置的扫描也有边界，诊断保留窗口限制、身份不匹配、不可用及缺少 PDF 等原因。

PMC 原 OA Web Service 已于 2026 年 8 月退役，本轮改用当前官方云端版本元数据提供的 pdf_url，不继续调用旧 oa.fcgi 或拼接 PMC PDF 地址。见 [PMC 退役公告](https://pmc.ncbi.nlm.nih.gov/tools/oa-service/)与[当前 AWS 获取说明](https://pmc.ncbi.nlm.nih.gov/tools/pmcaws/)。

route_attempts 保留实际尝试的阶段和结果，resolver_diagnostics 或 open_access_errors 保留解析失败。文件可解析但身份或版本尚不明时保留原件状态，并继续尝试其他允许的位置；只有目标满足才提前停止。

上述路线诊断在浏览器交回和最终校验后仍保留，当前成功或人工障碍状态单独更新；不要求为每篇论文另写证据卡。

retry_acquisition 为已有获取任务重新检查公开路径。它不删除成功原件，不抢占有效浏览器租约，不绕过 needs_user。来源重新可用与需要用户完成机构登录是两类状态，后者继续由显式恢复或人工确认处理。

## 显式版本关联和原件读取

当正式论文与预印本已经各自入库，只有提供方明确的版本关系才能建立 paper_relations。关系连接保留原有 paper_id、标识符、成员状态和原件归属，不靠相似题名删除或合并记录。

get_paper.related_paper_ids 及版本列表可查看关联；list_materials 同时给出实际材料及版本。严格正式版目标不能仅因关联预印本可读而成功，unknown 不自动变成 published。实际得到的版本与论文显示元数据应分开判断。

原始资料继续以 local_path、text_path、pages_path 提供给能够访问同机文件系统的科研 agent。缺少文件访问能力时使用 read_material；跨环境用 bundle 中的相对路径移交。新工作流不要求研究者放弃直接打开 PDF、代码或补充材料的方式。

## 本轮验证方法

使用真实 SQLite 和内核，注入可控的来源及学术图客户端，检查以下行为：既有库种子不冒充新命中、命中快照不受后续元数据更新污染、小预算种子续接、提供方错误分类、图分页去重与方向、取消传播，以及重试和版本策略。

真实复跑继续使用 RAG 评估和单细胞扰动两个既有用例。应保留旧记录，分开报告广检索召回、定向种子恢复、图扩展新候选、全文和版本可用性，以及仍需登录或浏览器的项目。比较必须说明预算、日期范围、来源和本轮实际执行阶段，不能将已有缓存直接当作新获取收益。

## 真实用例对照结果

最终复跑：2026 年 11 月 2 日 17:00 北京时间启动。使用[既有两个查询计划](use-cases.md)，每个主题查询仍给 4 次请求预算；按提供方工作单元检查，实际 RAG 为 4+4=8 次 HTTP，单细胞因 PubMed 两步请求为 5+4=9 次 HTTP。首个 frontier 的种子预算另计。种子恢复不受主题日期过滤，允许找回必要的基础论文，保留实际日期。引用扩展各给 8 次请求预算，不加日期过滤，既补基础参考也补后续研究。

| 指标 | RAG 评价 | 单细胞扰动 |
| --- | --- | --- |
| 本轮两个广检索的严格种子命中 | 0/2 | 1/3 |
| 两个广检索实际 HTTP 请求 | 8 | 9（比预算多 1） |
| 集成恢复后种子覆盖 | 2/2 | 3/3 |
| 种子恢复追加真实 HTTP 请求 | 2 | 3 |
| 引用扩展实际 HTTP 请求 | 7 | 8 |
| 相对本轮新集合新增引用候选 | 34 | 83 |
| 引用流完整返回数 | 4/4，保留索引缺口提示 | 0/6，4 条已有页面，2 条尚未执行；预算暂停 |
| 原固定纳入集合的全文 | 5/5 → 5/5 | 2/5 → 2/5 |

这里的新增候选按本轮集合去重，不是全局新发现的论文，也没有逐篇阅读或判定相关性。首轮已通过额外定向查询找回全部种子；本轮将这个恢复步骤变为组件接口，没有证明比所有其他策略更高的领域召回率。首轮宽松的标题/版本匹配为 RAG 0/2、单细胞 2/3，本轮按响应身份快照严格判断，两套广检索口径不可直接相减为提升比例。

RAG 两篇种子的前向索引分别返回 38 和 1 条连接；RAGChecker 实际读到第 2 页，无密钥旧游标导致的 401 已由官方普通分页解决。两篇的后向 referenced_works 当时为空，不能据此认为 PDF 没有参考文献。任务保留 partial 提示，不将索引遍历完成称作完整前沿覆盖。

单细胞 State 的预印本 DOI 与正式版已有明确的 bioRxiv 发表关系，原两个 ID 和原件归属保留；引用流记录正式版图入口与关系依据，未靠相似标题替换种子身份。预算暂停后的其他起点和后续页仍需继续运行。

### 全文实测与缺口

公开备用路线重试未增加两个固定集合的全文数。State 找回真实预印本入口，但与 Systematic Comparison 一样，在当前真实浏览器中要求 Cloudflare 人工验证；scPerturBench 仍要求机构登录。三项均为 needs_user，原件未取得，不自动反复重试人工障碍。

另外从现有 RAG 用例选择 RAGChecker，在**独立空库**重新请求真实元数据和 PDF：content.openalex.org 入口返回 401 后，实际切换至来源元数据给出的 arXiv PDF 并成功。原件 27 页、2,553,412 字节，首页标识 2408.08067v2，题名匹配通过。这证明失效/未授权入口不再阻断可用公开副本；它不是原集合的新增全文，也不代表所有获取失败已解决。

## 第二轮议会

开发和上述真实复跑完成后，三个独立视角交叉审查并复现版本身份、严格全文版本、模型任务续接、来源失败和成本口径问题。已采纳修复与回归、剩余边界和下一步见[第二轮议会记录](council-round2.md)。

修复后最终为 310 项常规测试通过，真实 MCP 检查单独通过；独立空库的真实 PDF 备用路线再次通过。议会解除所报阻塞，保留上文三项实际访问障碍和检索范围限制。
