# 项目接入和局部 AGENTS.md 管理

Research Base 将研究项目绑定到一个文献 collection，再提供可被宿主加载的短规则。研究者已有的项目说明、Vesti 区块及其他 agent 规则均保留。安装、卸载、冲突和恢复机制已实现；库名称映射等设计差异见[实现状态](implementation.md)。

## 接入方式

| 模式 | 提供的能力 | 生效条件 |
| --- | --- | --- |
| `manual` | 写项目配置，提供规则文本、CLI 和工具调用说明 | 研究者或工作流将说明放入实际使用的提示入口 |
| `agents` | 在目标项目根 AGENTS.md 追加受管区块 | 宿主实际加载该位置和文件名的规则 |
| 后续宿主适配 | skill 或阶段钩子调用 prepare_context | 宿主支持对应机制且适配器已启用 |

首版实现 manual 和 agents。MCP 连接只提供工具能力，不自动保证规则加载、上下文注入或 computer-use。doctor 检查文件与工具是否可用，并报告宿主规则加载情况为 `unverified`，除非完成了实际宿主演示。

不把 `.research/AGENTS.md` 作为唯一入口：它无法自然约束其他目录中的研究。默认将短规则直接写入项目根 AGENTS.md，减少额外跳转。文件名与宿主适配规则可以扩展，但不能假定一个名称被所有宿主识别。

## 项目定位和写入边界

`research-base attach --project PATH --collection ID --library-ref NAME --mode agents` 以明确的 PATH 为唯一项目写入边界。规范化为绝对路径后，配置、暂存写入文件、锁、恢复记录和入口都必须落在该项目内。

只读定位可从当前目录向上寻找最近的 `.research/config.yaml`，其次寻找 Git 根，再考虑当前目录。读取发现结果用于展示建议和查找已有绑定。首版写入命令 attach/detach 要求显式 --project，不自动把用户目录或任意祖先当作目标。

入口默认 `AGENTS.md`，如需指定其他文件只允许项目内的相对路径，并验证其实际解析位置。Windows 检查大小写变体；同时存在多个冲突入口时报告冲突。入口或配置通过符号链接、junction 指向边界外时，首版拒绝自动写入。

接入已有父级规则时仍按宿主优先级执行。组件区块不声明覆盖父级或用户规则；本地规则与已有要求有实质冲突时保留原文并给出差异，交给研究者处理。

## 项目配置和本机状态

[配置示例](../examples/project.research.yaml) 可提交到项目版本库，包含：

- schema_version、library_ref、预期 library_id 和 collection_id。
- 研究方向、启用来源、时间范围、全文获取策略和新鲜度偏好。
- integration.mode、entry_file、template_version。

逻辑 library_ref 在本机设置中映射到实际库目录。预期 library_id 用于避免另一台机器把同名引用指到不同的库。迁移研究资料时通过导入或显式重新绑定更新 ID，不静默回退。

运行状态放 `.research/state/`，如受管区块哈希、入口是否由组件创建、上次接入时间和中断写入记录。组件写配置时保留研究者的其他字段和设置，不将 attach 时的默认值覆盖到已有检索范围。

有效配置按显式请求参数、项目默认值、Collection 默认值依次取值。research 是项目方向说明，discovery/acquisition 等是本项目调用默认值，不是共享 Collection 的自动同步副本。attach、读取配置和 context 均不回写共享集合，修改共享默认值须显式 collection update。新鲜度按有效检索计划指纹匹配，不能沿用不同来源或查询范围的完成时间。

接入流程提示研究者忽略 `.research/state/`；也可通过显式的 `--update-ignore` 仅添加带标记的忽略行。首版默认不改 `.gitignore`。机密配置使用环境变量或本机设置，不能写入研究项目和模板。

## 受管规则

实际区块见[规则模板](../templates/AGENTS.research.md)。固定的起止标记为：

```text
<!-- research-base:managed:start -->
...Research Base 管理的短规则...
<!-- research-base:managed:end -->
```

规则通过 `.research/config.yaml` 查找集合，因此更换 collection 通常只需修改配置。规则表达四项要求：

1. 在研究问题分析、方法选择、实验设计、创新性评估和结果解释等关键任务前查询相关研究。
2. 依据当前任务读取必要的原文；涉及实现和复现时查看代码、实验设置及补充材料。
3. 判断前沿时检查新鲜度与覆盖缺口，需要时补充发现和获取；无法完成时说明实际限制。
4. 关键研究决策引用实际使用的文献，同时允许提出不同路线，不要求逐轮阅读报告或证据卡。

外部论文、网页和代码内容作为研究材料处理，不自动转成 AGENTS.md 指令。方向概览可以由研究者或 agent 维护，但组件不把原文中的命令直接写进项目规则。

## 安装 更新和卸载

### 安装

1. 检查目标项目、库身份、collection 和模式，解析可写边界。
2. 读取现有入口和配置，保存输入内容的哈希、编码及换行约定。支持 UTF-8、有或无 BOM；已有不支持编码的文件返回错误，不静默转码。
3. agents 模式下，无受管区块时追加模板，入口不存在时创建；模板和配置已一致则返回 unchanged。首次 manual 绑定只写配置并输出规则说明，不创建或修改入口。
4. 生成待写配置和区块差异。`--dry-run` 只输出拟修改路径与差异，不创建目录、锁或状态文件。
5. 使用项目短时锁，重新检查输入哈希，再写入和登记本机绑定状态。

已由明确接入命令授权的写入直接执行，不引入额外的审批步骤。出现用户内容冲突时返回冲突和候选差异，不能默认强制覆盖。

manual 切换到 agents 复用上述规则安装；agents 切换到 manual 复用安全移除区块流程，出现冲突则停止整次模式切换，不先把配置改为 manual。

### 更新

`attach` 既可安装也可重复执行更新。区块未被外部修改时，仅替换组件标记范围内的内容；区块外字节、原有 BOM 和换行保持不变。配置只更新本次显式指定的绑定或集成字段，其余设置保留。

如果当前区块与已保存哈希不符，返回 RULES_CONFLICT 并保留原文。若是新克隆项目尚无本机状态，只有区块与配置声明版本的已知模板完全一致时才可直接建立本机状态；其他情况展示差异，先人工解决。

出现半截标记、重复、嵌套区块或不明确的入口时停止自动更新，不猜测替换范围。模板升级保留旧模板版本用于识别；首版至少覆盖 v1 的安装、幂等更新和冲突检测。

### 卸载

`detach --project PATH` 只移除未经外部修改的受管区块，将配置的 integration.mode 改为 manual，保留研究范围、文献集合和原件。不恢复整个旧版入口，避免覆盖接入后新增的其他规则。

只有能证明入口由组件创建，且移除后仅剩空白时才删除入口文件。原有入口始终保留；无法确认来源时也保留。用户改过受管区块时返回冲突，待其手动处理。

已是 manual 且无受管区块的项目再次 detach 返回 unchanged；不存在绑定的项目不创建空配置、入口或状态文件。

## 写入一致性和中断恢复

入口和配置是两个文件，不能宣称普通文件替换提供跨文件原子事务。首版采用小型恢复记录，保存修改前后哈希及待写内容，临时文件位于目标同目录，通过单文件原子替换逐步完成。

恢复时先比较磁盘内容是否仍等于记录的修改前或修改后版本。只有匹配时才继续补齐操作；发现外部变化返回 RECOVERY_REQUIRED，保留内容并给出差异，不自动整文件回滚。跨平台支持情况在实际实现中检查。

组件自身操作由项目锁串行化，写前哈希检查用于检测外部编辑。外部编辑器不参加组件锁，因此这里只提供冲突检测和可恢复操作，不承诺能阻止所有同时写入。

## 运行时怎样使用文献

宿主开始关键研究任务时，先加载根规则，读取项目配置，通过 prepare_context 获取轻量入口。随后按任务读取原文或附件。若接口不可用，可以通过 CLI 调用同一能力；CLI 也不可用时明确报告组件尚未安装或库不可访问，不能声称已检查前沿。

建议的 CLI 入口为：

```text
research-base context --project . --task "当前研究任务"
```

该命令是 prepare_context 的命令行包装，项目只读定位规则同上。若项目下不同研究目录需要不同集合，首版通过显式不同 project_root 分别接入，或调用时显式 collection_id；不先实现复杂的自动目录路由。

宿主发现集合过期时，先调用 discover_papers，确定新增纳入项并触发 acquire_papers；需要浏览器的项由该宿主或其他工作者接续。无法立即拿到全文的项目保持可见，研究分析注明实际读取范围。

Skill 可将这些步骤写成使用方法，不复制内核逻辑。后续钩子可在任务启动和阶段变化时自动触发 prepare_context。两者都不作为模型确实理解或遵循论文的证明。

## Doctor 和接入验收

doctor 至少报告项目定位、库映射与身份、集合是否存在、配置版本、受管标记完整性、CLI/MCP 可用性、worker 与浏览器接续方式，以及宿主规则加载是否已验证。

验收必须覆盖空项目和已有规则项目，并保留包括 Vesti 在内的外部区块。重复接入无差异；更换集合仅改必要配置；用户修改区块会被检测；卸载后原有规则和资料保留；中断后能够恢复或清楚报告冲突。

最终用一个真实宿主演示“任务触发 → 查询集合 → 读取相关原件”。再通过手动说明或 skill 演示不自动加载 AGENTS.md 的工作流。演示证明接入链路可用，不把文件存在本身当作规则已生效。
