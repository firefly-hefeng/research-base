# 多 Agent 议会评审和改进记录

本页为首轮历史记录。本轮后续开发、两个真实用例复跑与交叉复评见[第二轮议会](council-round2.md)及[第二轮优化结果](optimization-round2.md)。

日期：2026 年 11 月 2 日。评审对象：Research Base 0.1.0 单机内测版。按研究者要求，先完成当前开发与真实用例，再组织三个独立视角的只读审查；发现的问题由实现方修复并回归验证。

## 议会组织

| 角色 | 检查重点 |
| --- | --- |
| 来源与获取 | 来源补充性和重叠、分页完整性、失效入口、公开替代路径、预算与新鲜度 |
| 数据与 Agent 接口 | 文献与版本身份、原件路径、书目迁入、默认集合范围、上下文和接口边界 |
| 研究流与真实用例 | 实际原文读取、项目规则加载、当前作者材料、科学表述、前沿覆盖和效率陈述 |

后续重要修改仍可按同样机制复评。每轮先选实际任务，再记录失败和材料缺口，独立提出问题，集中决定本轮修复或后置，最后用回归测试或真实任务验收。该机制在本项目内执行，不代表已设置周期自动化或后台常驻议会。

## 本轮决定和修复

| 问题 | 严重度 | 处理 |
| --- | --- | --- |
| 同一来源 ID 从预印本更新为正式发表时，可能改写原版本身份 | P1 | 版本类型或 DOI 身份变化时创建新版本，保留旧版本及材料；增加来源聚合更新回归 |
| 未明确版本的本地文件默认归入首选正式版 | P1 | 默认保持版本为空，按首页标识唯一推断或显式确认；未知原件可读，但不能满足严格正式版目标 |
| HTTP 200 的错误 JSON 可能被当作完整空结果 | P1 | 校验来源必需结构，异常返回 SOURCE_INVALID_RESPONSE，不能刷新完整检索时间 |
| 失效的已知 PDF 会阻断 DOI 或其他 OA 备用路径 | P1 | 当前路径耗尽后继续解析并尝试未请求过的公开位置，再进入浏览器 |
| 第一个身份不明文件导致后续正确 PDF 未被尝试 | P2 | 保存待确认原件，继续尝试替代路径，仅在满足目标时提前结束 |
| 小预算续接反复从第一个来源开始 | P2 | 持久化下一来源位置，跨续接轮询，减少来源饥饿 |
| Crossref 保存的游标过期后重复失败 | P2 | 显式 resume 可重启被提供方拒绝的游标，保留重新扫描状态并依赖标识去重 |
| 先导入 arXiv v2、再导入 v1 时首选项倒退 | P2 | 同一 arXiv 工作按明确版本号比较；无依据时保留首选项 |
| 超长标签导致导入报告与已写数据不一致 | P2 | 写入论文和成员关系前验证标签 |
| 模型读取全库冗余信息耗尽上下文 | P1 | 绑定集合成为默认范围，检索返回轻量元数据，保留原件入口；预算收尾不继续调用工具 |
| 科研计划混淆训练特征和评估 DE 基因、未核对 CPA 修正 | P1 | 对照原论文与作者 README 修订用例草稿，标注议会额外阅读范围，不将修订冒充原始模型回答 |

代码修复以对应测试为依据；科学方案修订仍需研究者根据实际实验条件复核。模型能读取材料不等于能够自动保证每项科学解释正确，本轮独立评审实际发现并纠正了这类问题。

二次复核已解除上述 P1：数据席确认版本身份修复，来源席确认异常响应不会更新完成状态，并再次通过受限真实接口请求。最终 202 项常规测试通过，真实 MCP 检查另行通过。议会结论收敛为“可按实验室单机内测边界使用，继续保留检索和全文缺口”。

## 当前发布边界

可用于实验室同机内测：书目迁入、多源候选收集、原件整理与路径读取、公开全文获取、浏览器任务交接、项目规则接入和有材料范围的科研方案辅助。可信本地 CLI/MCP 和可选 DeepSeek 共用内核。

真实用例证明这些链路能够接通，没有证明全领域检索已完成、模型方案可直接免复核执行，或通用浏览器能无人值守补齐所有订阅论文。单细胞用例中，Nature Methods 当前浏览器仅显示订阅预览，需要机构登录；任务已标 needs_user，没有当作取得全文。

## 下一轮优先项

1. 改进宽窄检索、种子召回与引用扩展。RAG 首轮广检索漏掉两篇已知种子，定向查询后找回；模型本次只筛了 27 条预筛候选，不是逐条审完全部发现记录。
2. 为大集合材料列表增加明确分页，继续减少元数据对上下文的占用。原件 ID 和路径保持稳定。
3. 评估引入 OpenAlex 官方批量下载后端、Zotero translator 或 Pubget/PMC XML 的收益，按真实失败分布选型，不为增加依赖而集成。
4. 用研究者准备的相关文献集合测试漏检、检索相关性、资料准备时间与任务质量。只有有可比的人工基准后，才报告效率改进比例。
5. 补充更正撤稿同步、完整备份恢复和远程服务模式；当前仍按单机内测边界使用。
